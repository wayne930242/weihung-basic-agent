# Rotating a long-lived session

A long-lived main (a standing session, or a coordinator that runs for days) rotates its session only on a concrete problem: `pi-session-doctor` measures repeated main-thread stalls the session's own state causes, or compaction has visibly lost context the work needs. A milestone, a long history, or a doctor nudge alone is no reason, because a new session starts without the prompt cache. To rotate, write `scratch/handoff-<name>.md` with the goal, the open todos only, the monitors and loops to recreate, the replies you owe and to whom, the branches and worktrees in flight, the loop's book id (the `book:` line of `anchorloop_stage read`), and the user's last instructions verbatim, then ask the user (or the tower that opened you) to start a new session from it. The new session reads the handoff, passes the book id as `resume` on its first `anchorloop_stage kind`, recreates the monitors and loops, takes the old main's kind with `boss_duty`, and drops completed todos. Then it tells the old session by intercom (the handoff names its id) that it took over. The old main then gives up its role, because towers route standing work by kind and name, and two standing mains of one name both get it: it runs `boss_duty coordinator` (when it was standing or integrator), renames itself with `boss_rename` to `old <name> (handed over to <new id>)`, stops its monitors and loops, clears its board, and waits for the user to close it. Never run `/new`, kill a process, or stop running work to rotate.
